# مهامي | المنظّم الدراسي الذكي

منصة عربية متجاوبة لعرض متطلبات الصفين الثاني والثالث الثانوي. مصدر المهام المركزي هو Google Sheets، بينما تُحفظ تفضيلات الطالب وعلامات الإنجاز على جهازه فقط. لا يوجد تسجيل دخول أو لوحة لإدارة المهام داخل الموقع.

## محتويات المشروع

- `index.html` واجهة الصفحة الواحدة، باتجاه RTL.
- `style.css` الهوية البصرية والتجاوب والوضع الليلي.
- `app.js` عرض المهام والبحث والتصفية والتخزين والتحديث.
- `config.js` خيارات الصفوف والشعب والمسارات ورابط API.
- `google-apps-script.gs` واجهة قراءة JSON لجدول Google.
- `tasks-template.csv` قالب فارغ بعناوين الأعمدة، للاستيراد إلى Google Sheets.
- `sample-tasks.csv` بيانات توضيحية للاختبار فقط، وليست بيانات دراسية حقيقية.

الشعب الافتراضية: ٢٠١ إلى ٢٠٥ للصف الثاني، و٣٠١ إلى ٣٠٥ للصف الثالث. يمكن تعديلها من `config.js` أو ورقة `Settings`.

## التشغيل في Visual Studio Code

1. افتح مجلد المشروع في Visual Studio Code.
2. افتح `index.html` مباشرة في المتصفح. لا يحتاج الموقع إلى Node.js أو خادم أو بناء ملفات.
3. عند ترك `apiUrl` فارغًا في `config.js` يعمل الموقع بوضع Demo ببيانات توضيحية مضمّنة في `app.js`، وتظهر عبارة «وضع تجريبي — بيانات للعرض فقط».
4. يمكن أيضًا فتح `index.html` عبر إضافة Live Server للتطوير. تشغيل نسخة GitHub Pages المنشورة لا يحتاج إلى Live Server.

## إعداد Google Sheets

1. أنشئ جدول بيانات جديدًا في Google Sheets.
2. أنشئ ورقة باسم `Tasks`، وضع صف العناوين التالي في الصف الأول، بالترتيب أو بأي ترتيب:

   `id, grade, section, track, subject, type, title, description, dueDate, teacher, link, priority, status`

3. ابدأ بإضافة صف لكل مهمة. استخدم معرفًا فريدًا ثابتًا لا يتكرر، مثل `task-2026-001`. القيم المقبولة للصف هي `2` و`3`، والشعبة مثل `201`، والمسار يجب أن يطابق اختيار المسار في الموقع.
4. اكتب الموعد بصيغة ISO 8601 مع توقيت الرياض، مثل `2026-11-03T20:00:00+03:00`. إذا كانت الخلية من نوع تاريخ في Sheets، ينسّقها Apps Script بتوقيت `Asia/Riyadh`. استخدم تاريخًا ووقتًا صريحين لتجنب اختلاف تفسير الخلايا التي تحتوي على تاريخ فقط. الوقت النصي بدون منطقة زمنية يُفهم على أنه توقيت الرياض.
5. الأنواع المدعومة: واجب، اختبار قصير، اختبار شهري، اختبار عملي، اختبار نهائي، مشروع، بحث علمي، ورقة عمل، عرض تقديمي، نشاط صفي، مهمة عملية، حفظ وتسميع، تقييم أداء، مشروع تخرج، أخرى.
6. الأولوية: `high` أو `medium` أو `low`. الحالة الافتراضية `active`. الصفوف التي حالتها `cancelled` أو `canceled` أو «ملغي» لا تظهر.
7. الروابط اختيارية؛ لا يعرض الموقع إلا روابط `https` أو `http`. تجنب وضع بيانات شخصية أو حساسة للطلاب في جدول عام.

### ورقة Settings الاختيارية

أنشئ ورقة باسم `Settings`، وضع `key` و`value` في أول صف. أضف الإعدادات كسطور، وقيمة كل إعداد تكون JSON صالحًا:

| key | value |
| --- | --- |
| `tracks` | `["عام","الصحة والحياة","علوم الحاسب والهندسة","إدارة الأعمال","الشرعي"]` |
| `subjects` | `["الرياضيات","الفيزياء","الكيمياء","الأحياء"]` |
| `sections` | `{"2":["201","202"],"3":["301","302"]}` |

يمكن تغيير القوائم أيضًا في `config.js`. إعدادات `Settings` المنشورة من API تتقدم على القيم الافتراضية في الموقع. أضف المواد المطلوبة فقط؛ لا يفترض الموقع أن المادة متاحة لكل المسارات.

## نشر Apps Script وإعداد API

1. من جدول البيانات افتح **الإضافات ← Apps Script**.
2. الصق محتوى `google-apps-script.gs` في ملف السكربت، ثم احفظ المشروع. السكربت مربوط بالجدول الحالي ويقرأ `Tasks` و`Settings` فقط.
3. من **نشر ← عملية نشر جديدة** اختر النوع **تطبيق ويب (Web app)**.
4. اختر التنفيذ بصلاحية مالك السكربت، وحدد الوصول العام المناسب لمؤسستك. اختر «أي شخص» فقط إذا كان نشر بيانات المهام للقراءة العامة مقبولًا؛ لا تنشر بيانات خاصة.
5. وافق على صلاحيات Google المطلوبة عند أول نشر، ثم أكمل النشر وانسخ رابط تطبيق الويب المنتهي عادةً بـ `/exec`.
6. افتح `config.js` وضع الرابط مكان القيمة الفارغة:

   ```js
   apiUrl: "https://script.google.com/macros/s/معرف_النشر/exec",
   ```

   سيستخدم الموقع `fetch` لقراءة JSON. لا تضع أي مفاتيح أو كلمات مرور أو بيانات اعتماد في ملفات الموقع. رابط النشر العام ليس سرًا.
7. إذا عدّلت كود Apps Script بعد نشره، أنشئ إصدار نشر جديدًا أو حدّث عملية النشر الحالية حسب واجهة Google Apps Script.

### صلاحيات الطالب المسؤول

امنح الطالب المسؤول صلاحية **Editor** على جدول Google Sheets نفسه من زر «مشاركة» في Google Sheets، باستخدام حسابه المدرسي إذا كان ذلك متاحًا. لا تشارك بيانات دخول مالك الجدول، ولا تمنحه صلاحيات على مشروع Apps Script أو حساب Google. يستطيع المحرر تعديل الجدول؛ أما الموقع فيبقى للقراءة فقط.

## نشر GitHub Pages

1. ارفع ملفات المشروع إلى مستودع GitHub عام، مع التأكد من ضبط `apiUrl` قبل النشر.
2. من إعدادات المستودع افتح **Pages**.
3. اختر النشر من الفرع الرئيسي ومجلد الجذر `/`، ثم احفظ.
4. انتظر ظهور رابط GitHub Pages وافتحه. المشروع ملفات ثابتة ولا يعتمد بعد النشر على خادم محلي.

## التحديث والخصوصية والقيود

- عند وجود رابط API، يطلب الموقع أحدث البيانات عند الفتح ثم كل 60 ثانية. يتوقف المؤقت عند إخفاء الصفحة ويُستأنف عند العودة.
- زر التحديث يجلب البيانات يدويًا. يعرض الموقع وقت آخر تحديث ناجح، وإذا فشل الاتصال يعرض آخر نسخة ناجحة محفوظة في `localStorage` مع تنبيه بأنها قديمة.
- عند إضافة مهام بمعرفات جديدة أثناء فتح الموقع يظهر تنبيه بصري بعد التحديث التالي. لا توجد إشعارات Push.
- الإنجاز والصف والشعبة والمسار والمظهر محفوظة محليًا في المتصفح، ولا تُرسل إلى Google Sheets ولا تنتقل لأجهزة أخرى.
- الرابط العام للـ Web App يجعل بيانات الجدول قابلة للقراءة لمن يحصل على الرابط، وقد تكون عامة وفق إعداد الوصول. انشر فقط بيانات دراسية غير حساسة، ولا تضف أسماء طلاب أو أرقامهم أو أي بيانات شخصية.
- لا يوفّر Apps Script في هذا المشروع نظام مصادقة للطلاب أو صلاحيات حسب الشعبة. إذا كان ذلك مطلوبًا، لا تجعل API عامًا؛ يلزم تصميم مصادقة مناسب قبل نشر أي بيانات.
- يعرض الموقع المحتوى النصي باستخدام DOM آمن، ويتحقق من صيغة التاريخ والرابط قبل الاستخدام. روابط `javascript:` وغيرها من البروتوكولات غير المسموحة لا تظهر.
- Google Fonts وLucide يُحمّلان من الإنترنت؛ إذا تعذر الاتصال بهما تستمر الوظائف الأساسية، لكن الخط أو الأيقونات قد تستخدم بدائل المتصفح.
- قد يحتاج نشر Apps Script إلى إعدادات مشاركة تسمح بـ `fetch` من المتصفح. اختبر رابط `/exec` من الموقع؛ سيظهر تنبيه اتصال بدل إخفاء الخطأ إذا لم يكن النشر أو الوصول مضبوطًا.

## اختبار التحديث

1. افتح الموقع واختر الصف والشعبة والمسار المطابقين لصف المهمة في الجدول.
2. أضف صفًا جديدًا في ورقة `Tasks` بمعرف مختلف وموعد صحيح.
3. انتظر حتى 60 ثانية أو اضغط زر التحديث؛ يفترض أن تظهر المهمة ويظهر تنبيه الإضافة.
4. عدّل عنوان المهمة في Sheets ثم حدّث؛ تتغير البيانات المعروضة. حالة «تم الإنجاز» تبقى محلية ولا تغيّر الجدول.
5. لاختبار وضع عدم الاتصال، بعد تحميل بيانات فعلية افصل الاتصال مؤقتًا أو أوقف النشر. ستظهر آخر بيانات API ناجحة المحفوظة مع تنبيه بأنها قديمة.
